# Evolution Car BY — две версии главной страницы

Перенос главной с Tilda (https://evcars-by.tilda.ws/) в код и вторая версия
той же страницы в стилистике https://zeekr.com.ru/. Тексты у обеих версий
одинаковые, различается только подача.

## Что где

Копия сайта с тильды (https://evcars-by.tilda.ws), 130 страниц:

- `/` — главная
- `/china/`, `/korea/`, `/europa/`, `/usa/` — страницы направлений
- `/catalog/` — каталог, 107 позиций из выгрузки Tilda Store
- `/catalog/<раздел>/` — in_stock, made_to_order, from_china, from_korea,
  from_europe, from_usa, electro_car, hybrid
- `/car/<slug>/` — карточка автомобиля, по одной на позицию
- `/about/`, `/contact/`, `/portfolio/`, `/rew/`, `/thank_page/`
- `/policy/`, `/agreement/`, `/legal_data/` — правовые
- `/zeekr/` — альтернативная главная в стилистике zeekr.com.ru

## Стек

- Astro (static) + Preact-острова. Острова общие для обеих версий,
  внешний вид задаётся токенами темы.
- Тексты только в `src/content/` — в компонентах не должно быть
  русских строк, иначе версии разъедутся.

## Структура

- `src/content/site.ts` — бренд, телефон, адреса, меню.
- `src/content/home.ts` — тексты всех секций главной.
- `src/content/cars.ts` — каталог: восемь моделей с характеристиками,
  описаниями, ценами и сроками поставки.
- `src/lib/seo.ts` — canonical, meta и блоки schema.org.
- `src/styles/base.css` — сброс, контейнер, кнопки, карточки.
- `src/styles/theme-v1.css`, `theme-v2.css` — семантические токены тем,
  скоуп `:root[data-theme="v1"|"v2"]`. Hex-значения живут только здесь.
- `src/styles/islands.css` — стили островов, на токенах.
- `src/components/v1/`, `src/components/v2/` — по 14 секций в каждой.
- `src/components/islands/` — `MobileMenu`, `LeadForm`, `Quiz`, `ModalHost`.
- `src/lib/submit.ts` — отправка заявки.
- `public/img/` — картинки, забранные с тильды + Unsplash для отзывов.

## Запуск

```
npm run dev      # astro dev
npm run build    # статика в dist/
```

Проверка вёрстки: собрать и поднять `dist/` статикой, снять скриншоты
на 375/768/1024/1440, убедиться что `scrollWidth === innerWidth`.

## Что не доделано

- **Уведомления о заявках не настроены.** Сами заявки сохраняются в базу и
  видны в админке, но Telegram и почта молчат: в `lead.env` на сервере не
  заданы `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS` и доступы к SMTP. Нужно
  решение, в какой чат и на какую почту их присылать.
- **Видео о сервисе** — исходника нет, в модалке стоит заглушка с постером.
- **Своей 404-страницы нет.** Сервер отдаёт её из корня статики, если файл
  есть; `src/pages/404.astro` пока не создан, поэтому на ошибочный адрес
  приходит стандартная заглушка.
- **Шрифты** подключены с Google Fonts. Tilda Sans проприетарный, в V1 вместо
  него Golos Text — ближайший по рисунку.
- **Отзывы** используют фотографии Unsplash — так же, как на самой тильде.
- **Фотографии в каталоге демонстрационные** и не соответствуют конкретным
  машинам. На странице модели об этом есть оговорка, но перед запуском нужны
  реальные фото от клиента.
- **Цены и характеристики в `cars.ts`** взяты из Figma-концепта и открытых
  данных по моделям. Перед публикацией их должен подтвердить клиент.
- **Домен-заглушка** `https://evolutioncar.by` в `astro.config.mjs` — от него
  зависят canonical и sitemap, нужно заменить на реальный.
- **robots.txt закрывает сайт целиком** — снять перед релизом вместе
  с `noindex` в BaseLayout.

## Сервер и админка

Сайт живёт в двух местах. На GitHub Pages — статика для показа, там нет
серверного процесса, поэтому ни заявок, ни админки. На VPS — тот же сайт,
но его отдаёт свой процесс, и там работают приём заявок и админка.

- `server/site_server.py` — один процесс: статика, `/api/lead`, `/admin`,
  защитные заголовки. Отдельный маршрут для API в общем конфиге Caddy был бы
  лишней точкой отказа: от этого файла зависят ещё около двадцати проектов.
- `server/lead_handler.py` — приём заявки: SQLite, затем Telegram и почта.
  Сохранение идёт до отправки, чтобы заявка не терялась при сбое доставки.
  Ловушка для ботов, лимит 5 заявок за 10 минут с адреса, обязательное согласие.
- `server/admin.py` — доступ по паролю, раздел «Страницы сайта», роутинг.
- `server/admin_leads.py` — заявки: доска по этапам, список, карточка, CSV.
- `server/admin_ui.py` — стили и каркас страниц админки.
- `server/page_seo.py` — карточка страницы: SEO, AEO, привязка к городу.

Этапы заявок: новая, связались, подбор, депозит, в пути, выдан, отказ.
Ключи этапов лежат в базе — переименовывать подписи можно, ключи нет.

Разделы «Метрика», «SEO-аналитика» и «Точка А» — заглушки: они требуют
внешних данных (счётчик, Вебмастер, Search Console, частотности по Беларуси).
Каждая заглушка перечисляет, чего не хватает, чтобы раздел заработал.

Выкладка: `scripts/deploy-vps.sh` — сборка без префикса подпапки, статика в
`/var/www/evolution-car-by`, серверный код в `/opt/evolution-car-by`,
перезапуск сервиса. Секреты и база — в `/opt/evolution-car-by/lead.env`
и `leads.db`, их синхронизация не затирает. Юнит — копия в
`server/evolution-car-by.service`. Адрес: `evolution-car-by.45.12.72.227.nip.io`
через Caddy на порт 8081.

**Админку из поиска видно быть не должно:** страницы отдаются с
`X-Robots-Tag: noindex` и `Cache-Control: no-store`, в них персональные
данные клиентов. В статику сайта админка не попадает.

## GitHub и публикация

- Репозиторий: `github.com/tema-mail/evolution-car-by`, основная ветка `main`.
- **Все изменения идут через git.** Правка без коммита не считается сделанной.
  История ведётся целиком: каждый завершённый шаг — отдельный коммит
  с описанием на русском, что и зачем поменялось.
- Пуш в `main` запускает сборку и публикацию на GitHub Pages:
  <https://tema-mail.github.io/evolution-car-by/>. Workflow — `.github/workflows/deploy.yml`.
- Перед пушем в `main` — локальная сборка `npm run build` без ошибок.
- `scripts/rebase-dist.mjs` дописывает префикс подпапки в готовую сборку:
  Pages отдаёт сайт из `/evolution-car-by/`, а в разметке пути корневые.
  При переезде на боевой домен этот шаг из workflow убирается,
  а в `astro.config.mjs` задаётся `PUBLIC_SITE_URL`.
- Секреты в репозиторий не попадают: `.env` в `.gitignore`, ключи и токены
  только в переменных окружения.

## Правила

- Файл кода ≤800 строк, один шаг — ≤3 файла, коммит после каждого шага.
- Mobile-first, `clamp()` для размеров, `minmax(0, 1fr)` в сетках.
- Hex-цвета в компонентах не писать — только токены темы.
